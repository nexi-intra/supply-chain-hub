# 1.4.0 — Update-readiness før release

Mål: 1.4.0 skal kunne installeres manuelt én gang på brugernes pc'er og derefter opdatere
sig selv fra den fælles M:-datamappe uden nye manuelle installationer.

## Fase 1 — Update-kanal og manuel install
- [x] Tilføjet `tcd-hub.config.json` i repoet med M:-datamappen som `dataDir`, så en ny
      manuel 1.4.0-installation kan finde fælles data + `updates/manifest.json` uden at
      brugeren først skal vælge datamappe.
- [x] Opdateret `scripts/build-release-v2.ps1`, så `tcd-hub.config.json` kopieres ved siden
      af `TCD Hub.exe` i `release/win-unpacked` og dermed også kommer med i ZIP-filen.

## Fase 2 — Updater robusthed
- [x] Delta-opdatering opretter nu altid staging-mappen, også hvis fil-diff er tom.
- [x] Apply-scriptet genstarter kun den gamle app og stopper, hvis `robocopy` fejler. Det
      fortsætter ikke til success/cleanup-flowet efter en mislykket filkopiering.
- [x] Apply-script-generering udtrukket til `buildApplyScript()`, så fail-flow kan testes
      uden at starte `wscript.exe`.
- [x] `updates:publish` afviser server-side at publicere samme/lavere version end den app,
      manageren kører, eller samme/lavere version end seneste manifest.

## Fase 3 — Automatiske tests
- [x] Test: delta-opdatering uden ændrede filer giver stadig gyldig staging-mappe.
- [x] Test: apply-scriptets robocopy-fejlgren starter appen og stopper før success-flowet.
- [x] Eksisterende tests dækker manifest, checksum-fejl, ZIP/full update, delta-copy,
      filindeks og obsolete files.

## Fase 4 — Verifikation og deploy
- [x] `npm run build`
- [x] `npm test` (17/17)
- [x] Pak 1.4.0 via `scripts/build-release-v2.ps1`
- [x] Bekræft `TCD-Hub 1.4.0/tcd-hub.config.json` findes ved siden af exe og peger på M:-datamappen.
- [x] Robocopy til lokal `TCD-Hub 1.4.0`
- [x] Commit ændringer.
