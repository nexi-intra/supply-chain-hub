# 1.4.0 Performance Diagnostics — Freeze/Lag-årsager

## Kritiske fund

### 1. **Synkron file I/O hver 2. sekund på network-drev** 🔴 HØJESTE PRIORITET
- **Sted:** `electron/store.cjs` linje 265+
- **Problem:** `fs.readdirSync()` + `fs.statSync()` poller hver 2000 ms, blokerer main-thread 50-500 ms per poll på netværksdrev
- **Impakt:** 15 klienter × 7-8 stat-kald per sekund samlet = konstant disk-IO
- **Løsning:** Byt til async watcher + debounce changes

### 2. **Synkron get()/set() på store JSON-filer**
- **Sted:** `electron/store.cjs` linje 90-110
- **Problem:** Hver `window.kv.get()` læser hele JSON-fil synkront; retry-loop kan vare 500+ ms ved network-latency
- **Impakt:** Komponenter der kalder `useKV()` på mount blokerer rendering
- **Løsning:** Cache sidst læste værdi lokalt, async reload i baggrund

### 3. **Masiv tabel uden virtualisering — ShiftSchedule**
- **Sted:** `src/views/ShiftSchedule.tsx` linje 740+
- **Problem:** Rendrer ~450+ DOM-knuder (30 dage × 15 medarbejdere) + dialogs + dropdowns
- **Impakt:** Scroll hakker, hover/click latency, React rec

onciliation slow
- **Løsning:** Virtualisering eller month-pagination

### 4. **IPC-broadcast-storm fra file-watcher**
- **Problem:** Hver fil-ændring → broadcast 'kv:changed' til alle vinduer → `useKV` hook trigger setState → re-render kæde
- **Impakt:** Hvis user skriver i formular + file ændrer sig samtidigt = lag spike
- **Løsning:** Batch/debounce broadcasts

### 5. **useKV hook kalder useEffect uden rigtig cleanup**
- **Sted:** `src/hooks/useKV.ts` 
- **Problem:** Abonnerer på kv.subscribe, som sender hele array på hver ændring
- **Impakt:** Selv hvis kun 1 felt ændrede sig får alle listeners arrayet
- **Løsning:** Granulær invalidation eller memoization
